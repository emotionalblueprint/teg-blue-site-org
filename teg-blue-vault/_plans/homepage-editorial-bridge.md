# Homepage Editorial Bridge

Status: active writing reference for `teg-blue.org`

This bridge combines the TEG-Blue Writing Protocol with Anna's professional
voice for public `.org` pages. It exists so later sessions can preserve the
same relationship between technical precision and readable public language.

## Governing Sequence

Use this order when introducing a TEG-Blue concept:

1. **Visible pattern** — begin with something a reader can recognise or observe.
2. **Plain meaning** — state what the pattern means in ordinary language.
3. **TEG-Blue term** — introduce the formal term only when it adds precision.
4. **Qualification** — name the boundary, uncertainty, or distinction that
   keeps the claim true.

> Visible pattern → plain meaning → TEG-Blue term → qualification

## Public `.org` Register

- Lead with the reader's question or the visible human pattern, not a
  classification of the framework.
- Build progressively: observation, relationship, term, mechanism, evidence,
  claim boundary.
- Prefer ordinary words where they carry the full meaning.
- Define specialised terms close to their first use.
- Let contrast make distinctions visible rather than stating conclusions alone.
- Keep sentences calm, observational, precise, and proportionate to the evidence.
- Cut prose that narrates the framework instead of helping the reader understand
  it.

## Distinctions That Must Survive Editing

- Position is not person, identity, personality, diagnosis, or severity.
- Environmental Conditions are not the same as the organism's read of them.
- Fluid movement is not the same as Chronic Survival organisation.
- Emotion is information, not automatic fact.
- Calm is not proof of safety; distress is not proof of danger.
- Mechanism explains a pattern; it does not erase impact or responsibility.
- Return is not recovery, repair, apology, compliance, exhaustion, or
  reconciliation.
- Actor-side reparation, harmed-person recovery, and relational rebuilding are
  separate territories.

Repetition is warranted when it protects one of these boundaries.

## Voice Check

Before publishing, ask:

- Does the first paragraph show the pattern before naming the architecture?
- Can each heading stand alone in a cold read?
- Does every abstract noun point to something observable?
- Does each technical term add precision and receive a nearby definition?
- Does the copy preserve power, impact, responsibility, safety, uncertainty,
  and source boundaries where they matter?
- Could the same meaning be carried with less effort?
- Does the ending complete the thought without becoming a slogan?

## Source Relationship

The TEG-Blue Writing Protocol protects ontology, surface-specific language, and
claim boundaries. Anna's professional voice supplies observation-led movement,
ordinary language, contrast, rhythm, and a quiet ending. Where style and
ontology conflict, ontology wins; the sentence is then rebuilt until it is both
accurate and easy to follow.
